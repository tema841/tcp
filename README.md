# TCP File Transfer — Windows

Консольная система передачи файлов между компьютерами по протоколу TCP/IP.

Проект использует **C++17** и поддерживает нативную сборку под Windows.
Основные сетевые операции выполняются через **Winsock 2**, а работа с
файлами — через стандартную библиотеку C++17.

## Возможности

- передача файлов от сервера к клиенту (`GET`);
- передача файлов от клиента к серверу (`PUT`);
- TCP/IP и IPv4;
- многопоточный сервер;
- несколько одновременных клиентов;
- передача фиксированными блоками (`chunk`);
- отображение прогресса;
- корректная обработка Ctrl+C / консольного завершения;
- временные `.part`-файлы при приёме;
- удаление неполного файла при ошибке;
- проверка пути внутри корневой директории сервера;
- интеграционные тесты.

# Запуск сервера

По умолчанию:

```powershell
.\server.exe
```

Порт:

```powershell
.\server.exe -p 4040
```

Корневая директория:

```powershell
.\server.exe -p 4040 -root .\storage
```

Например:

```powershell
mkdir storage
.\server.exe -p 4040 -root .\storage
```

Сервер будет принимать файлы только внутри указанной корневой директории.

Остановка:

```text
Ctrl+C
```

# Получение файла

Если на сервере находится:

```text
storage\file.txt
```

клиент запускается:

```powershell
.\client.exe `
    -p 4040 `
    -src 127.0.0.1:file.txt `
    -dst received.txt
```

После завершения:

```text
received.txt
```

появится в текущей директории клиента.

---

# Отправка файла

Например, есть:

```text
myfile.txt
```

Команда:

```powershell
.\client.exe `
    -p 4040 `
    -src myfile.txt `
    -dst 127.0.0.1:uploaded.txt
```

Файл появится на сервере:

```text
storage\uploaded.txt
```

---

# Размер блока

Размер блока задаётся параметром:

```powershell
-chunk 4096
```

Например:

```powershell
.\client.exe `
    -p 4040 `
    -chunk 4096 `
    -src 127.0.0.1:file.bin `
    -dst copy.bin
```

Допустимый диапазон:

```text
минимум: 1 KiB
максимум: 4 MiB
по умолчанию: 64 KiB
```

Размер блока влияет на количество операций чтения и отправки данных и может
использоваться как один из параметров экспериментального исследования
эффективности передачи.

# Протокол

Клиент и сервер используют простой текстовый управляющий протокол.

## GET

Запрос:

```text
GET file.bin 65536
```

Ответ:

```text
OK 123456
```

где `123456` — размер файла в байтах.

После ответа сервер передаёт содержимое файла.

## PUT

Запрос:

```text
PUT file.bin 123456 65536
```

где:

- `file.bin` — имя файла;
- `123456` — размер файла;
- `65536` — размер блока.

Ответ:

```text
OK
```

После этого клиент отправляет содержимое файла.

---

# Работа с неполными файлами

При получении файл сначала записывается во временный файл:

```text
file.bin.part
```

Только после полного получения данных он переименовывается:

```text
file.bin
```

Если соединение разорвано или передача остановлена:

```text
file.bin.part
```

удаляется.

Таким образом, основной файл не заменяется неполными данными.

---

# Безопасность пути

Сервер использует параметр:

```text
-root
```

как корневую директорию хранилища.

Запросы, которые пытаются выйти за её пределы, например:

```text
../../secret.txt
```

отклоняются.

Абсолютный путь разрешается только в том случае, если он находится внутри
настроенной корневой директории.

# Тестирование

Интеграционные тесты проверяют:

- запуск сервера;
- GET с размером блока по умолчанию;
- GET с указанным размером блока;
- GET по абсолютному пути внутри root;
- запрос отсутствующего файла;
- неизвестные команды;
- слишком маленький размер блока;
- слишком большой размер блока;
- попытку обхода корневой директории;
- некорректный размер файла в PUT;
- обычный PUT;
- передачу пустого файла;
- работу клиента GET;
- работу клиента PUT;
- некорректные аргументы клиента;
- подключение без запроса;
- корректное завершение сервера при консольном сигнале.

# Отличия Windows-версии от Linux-версии

В Linux использовался POSIX API:

```text
socket()
close()
fork()
exec()
dlopen()
```

В Windows сетевой слой переведён на:

```text
Winsock 2
SOCKET
closesocket()
WSAStartup()
WSACleanup()
```

Для параллельной обработки клиентов по-прежнему используется:

```cpp
std::thread
```

а работа с файлами остаётся основанной на:

```cpp
std::filesystem
std::ifstream
std::ofstream
```

Поэтому основная логика передачи файлов не зависит от конкретной операционной
системы.
