# Adaptive TCP Transfer

Курсовой проект: **разработка системы адаптивной передачи данных с мониторингом сети**.

Система сохраняет исходную идею TCP File Transfer, но превращает её в законченный исследовательский стенд: несколько клиентов, возобновление передачи, SHA-256, автоматический подбор размера блока, web-мониторинг и нагрузочный тест.

## Что реализовано

- TCP/IP, IPv4, Windows/Linux, C++17;
- одновременная работа клиентов через `std::thread`;
- GET и PUT;
- возобновление по `.part` для скачивания и загрузки;
- проверка целостности SHA-256;
- адаптивный chunk: стартует с заданного значения и изменяется от измеренной скорости;
- мониторинг активных передач: файл, клиент, направление, прогресс, скорость, chunk, состояние;
- встроенная web-панель без отдельного сервера;
- нагрузочный стенд `tools/load_test.py`;
- безопасная корневая директория `-root`;
- CMake + Makefile;
- базовый unit-тест SHA-256.

## Запуск Windows

Соберите через Visual Studio 2022/CMake или MinGW-w64:

```powershell
cmake -S . -B build
cmake --build build --config Release
```

Запустите:

```powershell
mkdir storage
.\build\server.exe -p 4040 -web-port 8080 -root .\storage -web .\web
```

Откройте **http://127.0.0.1:8080**.

Если используется multi-config генератор Visual Studio, исполняемый файл обычно будет в `build\Release\` или `build\bin\Release\` в зависимости от конфигурации проекта.

## Передача

GET:

```powershell
.\build\client.exe -p 4040 -src 127.0.0.1:file.bin -dst copy.bin
```

PUT:

```powershell
.\build\client.exe -p 4040 -src big.bin -dst 127.0.0.1:uploaded.bin
```

Параметр chunk:

```powershell
-chunk 65536
```

Диапазон: 4 KiB–4 MiB. По умолчанию 64 KiB.

Для демонстрации возобновления можно остановить клиента во время большой передачи и повторить ту же команду: незавершённая часть будет продолжена.

## Как работает адаптация

Передача идёт блоками с длиной каждого блока. Клиент/сервер измеряет фактическую скорость на коротком окне. Если скорость устойчиво выросла, размер блока увеличивается; если заметно упала — уменьшается. Границы: 4 KiB–4 MiB.

Это не утверждение, что один chunk оптимален для любого интернета: именно поэтому в проекте предусмотрено экспериментальное сравнение. Для курсовой можно исследовать 4, 16, 64, 256, 1024 и 4096 KiB при разных размерах файлов и количестве клиентов.

## Web API

`GET /api/status` возвращает JSON с текущими передачами. Панель сама обновляется раз в секунду.

## Нагрузочный стенд

Подготовьте большой файл и запустите сервер. Затем:

```powershell
python tools/load_test.py --file big.bin --clients 4 --repeats 2
```

Количество клиентов можно менять: `1`, `2`, `4`, `8` и т.д. Для сравнения фиксированного chunk:

```powershell
python tools/load_test.py --file big.bin --clients 4 --chunk 4096
python tools/load_test.py --file big.bin --clients 4 --chunk 65536
python tools/load_test.py --file big.bin --clients 4 --chunk 1048576
```

Полученные времена и скорости можно заносить в таблицу эксперимента. Для более серьёзного исследования следует повторять каждый сценарий несколько раз и считать среднее значение.
